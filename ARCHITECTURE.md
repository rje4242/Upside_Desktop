# upside2-md Architecture

## Overview

upside2-md is a coarse-grained protein molecular dynamics engine. Each residue is represented by three backbone atoms (N, CA, C) plus virtual sidechain centroids; all-atom detail is recovered on-the-fly through rotamer libraries. The system is split into a C++ simulation engine and a Python layer for configuration, submission, and analysis.

```
┌─────────────────────────────────────────┐
│          Python Layer (py/)             │
│  PDB_to_initial_structure.py            │
│  upside_config.py  ←─ force field       │
│  run_upside.py     ←─ parameters/       │
│  mdtraj_upside.py  (analysis)           │
└────────────────┬────────────────────────┘
                 │  .up HDF5 file
                 ▼
┌─────────────────────────────────────────┐
│         C++ Engine (src/)               │
│  main.cpp  (CLI + MD loop)              │
│  deriv_engine  (auto-diff graph)        │
│  potentials  (force field terms)        │
│  thermostat / integrator                │
│  h5_support  (HDF5 I/O)                 │
└─────────────────────────────────────────┘
```

## Build System

`install.sh` generates `source.sh`, then runs CMake from `src/` into `obj/`.

CMake dispatches to one of two platform-specific files:

| File | Target |
|---|---|
| `src/CMakeLists_Other.txt` | x86-64 Linux |
| `src/CMakeLists_M1.txt` | Apple ARM (M1/M2/M3) |

Both targets build:
- **`obj/upside`** — standalone MD binary
- **`obj/libupside.so`** — shared library for Python in-process calls

Compiler flags: `-O3 -ffast-math -march=native` with OpenMP.

External dependencies: HDF5 (C interface), Eigen3 (header-only linear algebra, found via `find_package(Eigen3)`), OpenMP.

## C++ Engine

### Automatic Differentiation Graph (`deriv_engine.h/.cpp`)

The computational core is a directed acyclic graph (DAG) of typed nodes. The graph is built once at startup from the `/input/potential/` HDF5 group and then executed every MD timestep.

**Node types:**

| Class | Role |
|---|---|
| `Pos` | Entry point — atomic position array; written by the integrator |
| `CoordNode` | Computes geometry (distances, angles, dihedrals, placements). Holds `output` and `sens` arrays. |
| `PotentialNode` | Computes a scalar energy. Accumulates into total potential. |

Execution proceeds in two phases each timestep:

1. **Forward pass** — nodes compute `output` (values) bottom-up.
2. **Backward pass** — nodes propagate `sens` (∂E/∂output) top-down back to `Pos.sens`, which becomes the force.

This scheme means every force field term only needs to implement its value computation; derivatives are handled by the chain rule automatically.

### MD Loop (`main.cpp`)

Each replica is a `System` struct containing:
- `DerivEngine engine` — the computation graph
- `VecArray mom` — momentum (velocity × mass)
- `OrnsteinUhlenbeckThermostat thermostat`
- `H5Logger logger`

The main loop per timestep:

```
1. (optional) Monte Carlo pivot/jump move
2. Compute derivatives (forward + backward passes)
3. Velocity Verlet or multi-step Verlet position update
4. Apply Ornstein-Uhlenbeck thermostat (stochastic momentum rescaling)
5. Recenter COM (disabled or XY-only for membranes)
6. (optional) Attempt replica exchange swaps
7. (optional) Log trajectory frame
```

### Integrators

| Flag | Integrator |
|---|---|
| `--integrator v` | Standard Velocity Verlet |
| `--integrator mv` | Multi-step Verlet (inner steps controlled by `--inner-step`) |

Multi-step Verlet uses smaller inner steps for stiff high-frequency degrees of freedom (backbone bonds) while the outer step controls the thermostat and MC frequency.

### Thermostat (`thermostat.h/.cpp`)

Ornstein-Uhlenbeck stochastic rescaling:

```
p ← exp(-Δt/τ) · p  +  √(T · (1 - exp(-2Δt/τ))) · ξ
```

where τ is `--thermostat-timescale` (default 5.0) and ξ is white noise. This preserves the canonical ensemble exactly.

### Replica Exchange (`main.cpp`)

`ReplicaExchange` manages N replicas at different temperatures. Swap sets are specified as comma-separated pair strings (e.g., `"0-1,2-3"`); multiple `--swap-set` arguments allow staggered exchange patterns.

Metropolis criterion at swap attempt between replicas i and j:

```
ΔlogP = (βi − βj)(Ei − Ej)       [mode 0: total energy]
accept if ΔlogP ≥ 0 or exp(ΔlogP) > U(0,1)
```

Failed swaps are reversed in-place. The replica index array in the output records which physical replica occupies each temperature slot over time.

### Membrane Curvature (`main.cpp`)

`CurvatureChange` performs Metropolis moves on the Z-position of the `Const3D_curvature_center` node, which shifts the effective membrane center. Activated by `--curvature-changer-interval`. Used in dynamic curvature examples (08.MembraneSimulation/4–5).

### Monte Carlo Moves (`monte_carlo_sampler.h/.cpp`)

`MonteCarloSampler` (base) and `MultipleMonteCarloSampler` manage:
- **Pivot moves** — rotate a backbone segment around a bond
- **Jump moves** — translate a chain segment

All moves use Metropolis accept/reject against the current potential energy.

## Force Field Terms

All terms are `CoordNode` or `PotentialNode` subclasses loaded from the `/input/potential/` HDF5 group.

| Node | File | Description |
|---|---|---|
| `placement_*` | `placement.cpp` | Reconstruct N, CA, C, O, CB, H from backbone dihedrals |
| `generate_from_rotamer` | `generate_from_rotamer.cpp` | Place sidechain atoms from selected rotamer |
| `hbond` | `hbond.cpp` | H-bond geometry scoring with directional spline energy |
| `rama_map_pot` | `rama_map_pot.cpp` | Ramachandran φ/ψ map potential |
| `rotamer` | `rotamer.cpp` | Discrete sidechain rotamer states; 1-body and 2-body energies |
| `environment` | `environment.cpp` | Burial/solvent exposure potential |
| `backbone_steric` | `backbone_steric.cpp` | Cα–Cβ excluded volume |
| `sidechain_radial` | `sidechain_radial.cpp` | Cavity / radial packing potential |
| `membrane_potential` | `membrane_potential.cpp` | Z-dependent residue insertion energy |
| `surface` | `surface.cpp` | Implicit membrane surface term |
| `spring` | `spring.cpp` | Harmonic position restraints |
| `tension` | `tension.cpp` | Pulling force along an axis |

Energy splines throughout the code use clamped cubic B-splines (`spline.h`) evaluated per-atom with analytic gradients.

## HDF5 `.up` File

The `.up` file is the single portable artifact that carries everything needed to run or restart a simulation.

### `/input/` group — written by `upside_config.py`

```
/input/
├── pos                     [n_atom, 3, 1]   initial coordinates
├── mom                     [n_atom, 3, 1]   momentum (restart only)
├── fasta                   [n_residue]       amino acid sequence
├── chain_first_residue     [n_break]         chain break indices
└── potential/              computational graph
    ├── pos/                Pos entry node
    ├── placement_*/        backbone reconstruction nodes
    ├── rotamer_*/          sidechain rotamer nodes
    ├── hbond/              hydrogen bond node
    ├── rama_map_pot/       Ramachandran node
    ├── environment_*/      burial nodes
    ├── membrane_potential/ membrane node (optional)
    └── [spring, tension, surface, ...] (optional)

Each node group contains:
    arguments  [HDF5 attr]  list of input node names
    [node-specific datasets: indices, spline knots, parameters]
```

### `/output/` group — appended by `upside` during simulation

```
/output/
├── pos                     [n_frame, n_atom, 3]    trajectory
├── potential               [n_frame]                total potential energy
├── kinetic                 [n_frame]                kinetic energy per atom
├── time                    [n_frame]                simulation time
├── temperature             [n_frame, n_replica]     thermostat temperature
│
├── (DETAILED log-level)
│   ├── hbond_*             per-H-bond occupancy
│   └── environment_*       per-residue burial
│
├── (EXTENSIVE log-level)
│   └── rotamer_state_*     selected χ angles per frame
│
└── (replica exchange)
    ├── replica_index               [n_frame, n_replica]    T-slot assignment
    └── replica_cumulative_swaps    [n_frame, n_pair, 2]    success/attempt counts
```

On restart (`continue_sim = True`), `upside_config.py` renames `/output` → `/output_previous_N` and resets `/input/pos` to the last frame, allowing chains of runs in a single file.

## Python Layer

### Configuration pipeline

```
PDB_to_initial_structure.py
    Input:  protein.pdb
    Output: protein.fasta
            protein.initial.npy   (N×3 backbone coords)
            protein.chi           (sidechain angles)
            protein.chain_breaks  (inter-chain indices)

upside_config.py  [called via run_upside.upside_config()]
    Reads:  .fasta, .initial.npy, parameter HDF5/dat files
    Writes: simulation.up  (/input group only)

advanced_config.py  [called via run_upside.advanced_config()]
    Opens:  simulation.up in append mode
    Adds:   custom constraints (Const3D, affine alignment, nail files, etc.)
```

### `upside_config()` key arguments

| Argument | Type | Purpose |
|---|---|---|
| `fasta` | str | Sequence file path |
| `output` | str | Output `.up` path |
| `initial_structure` | str | `.npy` backbone coords |
| `rama_library` | str | Ramachandran reference |
| `hbond_energy` | str | H-bond parameter HDF5 |
| `rotamer_placement` | str | Sidechain library HDF5 |
| `rotamer_interaction` | str | 2-body interaction HDF5 |
| `environment_potential` | str | Burial potential HDF5 |
| `membrane_potential` | str | Z-depth potential HDF5 |
| `membrane_thickness` | float | Membrane half-thickness (Å) |
| `use_curvature` | bool | Enable curved membrane |
| `curvature_radius` | float | Radius of curvature (Å) |
| `curvature_sign` | int | +1 / -1 curvature direction |
| `chain_break_from_file` | str | Multi-chain break indices |

### In-process calls (`upside_engine.py`)

`libupside.so` exposes a C interface (`engine_c_library.h`) with functions:
- `upside_main(argc, argv, verbose)` — run simulation
- `evaluate_energy()` — single-point energy
- `evaluate_deriv()` — energy + gradient
- `set_param()` / `get_output()` — parameter perturbation

Python accesses these via `ctypes`. `run_upside.in_process_upside()` wraps `upside_main` for scripted runs without spawning a subprocess.

### Analysis tools

| Script | Purpose |
|---|---|
| `mdtraj_upside.py` | Load `.up` trajectory into MDTraj |
| `extract_vtf.py` | Export to VMD VTF format |
| `get_info_from_upside_traj.py` | Frame-level statistics |
| `get_protection_state.py` | H-bond / burial analysis |
| `generate_restart_config.py` | Build restart `.up` from trajectory |

## `upside` CLI Reference

Positional arguments: one or more `.up` files (one per replica).

| Flag | Default | Description |
|---|---|---|
| `--duration FLOAT` | required | Total simulation time |
| `--frame-interval FLOAT` | required | Steps between logged frames |
| `--temperature FLOAT[,...]` | 1.0 | Comma-separated temperature per replica |
| `--seed LONG` | 42 | RNG seed |
| `--time-step FLOAT` | 0.009 | Integration timestep |
| `--integrator v\|mv` | v | Verlet or multi-step Verlet |
| `--inner-step INT` | 3 | Inner steps for `mv` integrator |
| `--thermostat-timescale FLOAT` | 5.0 | OU thermostat relaxation time |
| `--replica-interval FLOAT` | 0 | Steps between swap attempts (0 = off) |
| `--swap-set STRING` | — | Replica pair groups; repeat for staggered sets |
| `--monte-carlo-interval FLOAT` | 0 | Steps between MC moves (0 = off) |
| `--curvature-changer-interval FLOAT` | — | Steps between curvature MC moves |
| `--disable-recentering` | — | Skip COM recentering |
| `--disable-z-recentering` | — | Only recenter in XY (membrane simulations) |
| `--log-level basic\|detailed\|extensive` | detailed | Output verbosity |
| `--anneal-factor FLOAT` | 1.0 | Final temperature multiplier for annealing |

Signal handling: `SIGTERM` and `SIGINT` trigger a graceful shutdown that flushes all buffered output before exit. Useful under SLURM time limits.
